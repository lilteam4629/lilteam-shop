# LilTeam Shop

เว็บร้านขายไอดีเกม Steam (ออฟไลน์ + เช่ารายวัน) พร้อมระบบหลังบ้านเต็มรูปแบบ
สร้างด้วย Node.js + Express + EJS + Tailwind CSS (CDN) — ไม่ต้องใช้ build step

## เริ่มต้นใช้งาน

```bash
npm install
cp .env.example .env   # (ไม่บังคับ ดูหัวข้อ "ระบบเก็บข้อมูล" ด้านล่าง)
npm start
```

เปิด `http://localhost:3000`

**บัญชีทดลอง:**
- ลูกค้า: `demo` / `demo1234`
- แอดมิน: `admin` / `admin1234` (เข้าหลังบ้านที่ `/admin`)

## โครงสร้างโปรเจกต์

```
src/
  app.js              # จุดเริ่มต้นแอป, ตั้งค่า middleware, mount routes
  data/
    store.js          # ชั้นข้อมูล (MongoDB Atlas หรือ fallback เป็นไฟล์ JSON)
    db.json           # ข้อมูลตัวอย่าง (สร้างอัตโนมัติถ้ายังไม่มี, ไม่ commit ขึ้น git)
  middleware/
    auth.js           # attachUser, requireLogin, requireAdmin
  routes/
    shop.js            # หน้าร้าน: หน้าแรก, รายการสินค้า, หน้าสินค้า, ค้นหา
    auth.js            # login / register / logout
    cart.js             # ตะกร้าสินค้า, checkout
    account.js          # บัญชีลูกค้า, ประวัติคำสั่งซื้อ, ขอโค้ด Steam Guard
    admin.js             # ระบบหลังบ้านทั้งหมด (สินค้า, ตัวกรอง, ออเดอร์, สมาชิก, คูปอง, ประกาศ, ตั้งค่า)
  views/
    layouts/            # เลย์เอาต์หลัก (หน้าร้าน / หลังบ้าน)
    partials/            # ส่วนประกอบซ้ำ (navbar, footer, product-card, filter-panel)
    shop/                # หน้าต่างๆ ของหน้าร้าน
    admin/               # หน้าต่างๆ ของหลังบ้าน
public/                # ไฟล์ static (css, img)
```

## ระบบเก็บข้อมูล

โปรเจกต์นี้รองรับ 2 โหมด สลับอัตโนมัติตามว่ามีตัวแปรแวดล้อม `MONGODB_URI` หรือไม่:

- **มี `MONGODB_URI`** → เก็บข้อมูลถาวรบน MongoDB Atlas (แนะนำสำหรับ production/deploy จริง)
- **ไม่มี** → fallback ไปใช้ไฟล์ `src/data/db.json` (สะดวกสำหรับ dev ในเครื่อง แต่ข้อมูลจะรีเซ็ตถ้าลบไฟล์หรือ deploy ใหม่บน hosting ที่ดิสก์ไม่ถาวร)

ดูวิธีตั้งค่า MongoDB Atlas แบบละเอียดได้ใน [.env.example](.env.example)

หากเข้าแอดมินไม่ได้ ให้ตั้ง `ADMIN_USERNAME` และ `ADMIN_PASSWORD` ใน Environment Variables ของโฮสต์แล้ว Deploy ใหม่ ระบบจะกู้สิทธิ์และเปลี่ยนรหัสของบัญชีแอดมินให้โดยไม่ลบข้อมูลร้าน

โครงสร้างข้อมูลทั้งหมด (settings, products, filterTags, stockItems, orders, coupons, announcements, users, reviews, walletTransactions) นิยามไว้ที่ `defaultData()` ใน `src/data/store.js` — นี่คือจุดเดียวที่ควรดูเพื่อเข้าใจ schema ทั้งหมดของระบบ

## ฟีเจอร์หลัก

**หน้าร้าน**
- แยกสินค้า 2 ประเภท: ไอดีออฟไลน์ (ราคา + ราคาปกติขีดฆ่า) / ไอดีเช่ารายวัน
- ตัวกรองสินค้าแบบเลื่อนแนวนอน จัดการรูป/ชื่อได้จากหลังบ้าน ผูกกับสินค้าได้อิสระ
- ตะกร้า + คูปองส่วนลด + ชำระด้วยกระเป๋าเงิน (จำลอง ไม่ใช่ payment gateway จริง)
- ระบบขอโค้ด Steam Guard (จำกัด 3 ครั้ง/ออเดอร์)
- เอฟเฟกต์: mouse-tracking spotlight บนการ์ดสินค้า, animated stat counters

**หลังบ้าน** (`/admin`, ต้องเป็น role `admin`)
- จัดการสินค้า, สต๊อกไอดี (username/password), ตัวกรองสินค้า
- จัดการคำสั่งซื้อ, สมาชิก (ปรับยอดกระเป๋าเงิน, ระงับบัญชี), คูปอง, ประกาศ, ตั้งค่าร้าน

## ให้คนอื่นเช่าระบบนี้ไปเปิดร้านเอง

ทุก deploy (โปรเจกต์ Railway หนึ่งชุด) เป็นร้านค้าอิสระของตัวเอง ไม่แชร์ข้อมูลกัน — วิธีปล่อยเช่า:

**1. สร้างเว็บใหม่ให้ผู้เช่า (ทำจากมือถือได้ผ่าน Railway dashboard, ทำครั้งเดียวตอนเป็นลูกค้าใหม่)**
- สร้างโปรเจกต์ Railway ใหม่จาก repo นี้ (Deploy from GitHub repo)
- ตั้งค่า Environment Variables: `ADMIN_USERNAME`, `ADMIN_PASSWORD` (ของผู้เช่า), `MONGODB_URI` (แนะนำ Atlas free tier ดูวิธีด้านบน), `LICENSE_SECRET` (ค่าลับเดียวกับที่ตั้งไว้ในร้านของคุณเอง — ดูข้อ 2), และ `LICENSE_GATE=on` (บังคับให้ต้องกรอกคีย์ก่อนใช้งานได้)
- Deploy เสร็จได้ URL เว็บร้านใหม่ ส่งให้ผู้เช่าไปกรอกคีย์ (จากข้อ 2) ที่หน้า `/license`

**2. ระบบขายคีย์อัตโนมัติในร้านของคุณเอง (ไม่ต้องทำอะไรมือหลังจากตั้งค่าครั้งแรก)**

ตั้ง `LICENSE_SECRET` (ค่าลับที่คุณกำหนดเอง) ไว้ใน **ร้านของคุณเอง** ด้วย (แต่**ห้ามตั้ง** `LICENSE_GATE` ที่ร้านตัวเอง ไม่งั้นร้านคุณจะถูกล็อก) — พอตั้งเสร็จ ระบบขายคีย์จะเปิดใช้งานทันที:

- ไปที่ **Admin Panel → 🌐 ขายคีย์เช่าเว็บ** ตั้งแพ็กเกจ (เช่น 7 วัน ฿199 / 30 วัน ฿599 / 90 วัน ฿1,499) ราคา/จำนวนวันปรับได้เอง
- ลูกค้า (ทั้งผู้เช่าใหม่และผู้เช่าเดิมที่จะต่ออายุ) เข้าหน้า **`/rent-website`** ในร้านคุณ เลือกแพ็กเกจ กดซื้อ จ่ายด้วยกระเป๋าเงินในระบบ (เติมเงินผ่าน SlipOK ได้ตามปกติ) — **ระบบออกคีย์ให้ทันทีอัตโนมัติ ไม่ต้องมีคุณมายุ่งเลย**
- คีย์ที่ได้เอาไปกรอกที่หน้า `/license` ของเว็บร้านผู้เช่า (เว็บใหม่จากข้อ 1 หรือเว็บเดิมที่จะต่ออายุ) ปลดล็อก/ต่ออายุได้ทันที
- ดูประวัติการขายทั้งหมดได้ที่หน้าเดียวกันในแอดมิน (ผู้ซื้อ, จำนวนวัน, ราคา, คีย์)

**3. หลังจากนั้นผู้เช่าตั้งค่าร้านเอง** ทั้งหมดผ่านหน้า `/admin` ของเว็บเขา (ชื่อร้าน โลโก้ บัญชี/QR รับเงิน สินค้า มินิเกม ฯลฯ) ไม่ต้องพึ่งคุณอีกเลย นอกจากตอนต่ออายุที่เขาซื้อคีย์เองได้จากข้อ 2

**4. เปิดเว็บใหม่แบบอัตโนมัติเต็มรูปแบบ — ลูกค้าออกค่าใช้จ่ายเอง (ไม่บังคับ)**

ถ้าตั้งค่า `RAILWAY_TEMPLATE_REPO` ไว้ที่ **ร้านของคุณเอง** (ดู `.env.example`) หน้า `/rent-website` จะมีช่อง **"🆕 เปิดเว็บใหม่ของคุณเอง"** เพิ่มมาให้ลูกค้ากรอก โดยลูกค้าต้องกรอก **Railway API Token ของตัวเอง** และ **MongoDB URI ฟรีของตัวเอง** (มีปุ่มลิงก์ตรงไปหน้าสร้าง token / สมัคร MongoDB Atlas ให้ในฟอร์มเลย ไม่ต้องอ่านคู่มือแยก) ตอนซื้อระบบจะ:
1. สร้างโปรเจกต์ใหม่บน **บัญชี Railway ของลูกค้าเอง** ให้อัตโนมัติ (ผ่าน Railway GraphQL API โดยใช้ token ที่ลูกค้ากรอก)
2. ตั้งค่า `ADMIN_USERNAME`/`ADMIN_PASSWORD` ตามที่ลูกค้ากำหนดเอง
3. ใช้ `MONGODB_URI` ที่ลูกค้ากรอกมา (ฐานข้อมูลของเขาเอง แยกขาดจากร้านคุณสนิท)
4. ตั้ง `LICENSE_GATE=on` พร้อมผูกคีย์ที่เพิ่งซื้อให้ทันที
5. สั่ง deploy และสร้างโดเมนสาธารณะ (`*.up.railway.app`) ให้

ลูกค้าจะเห็นสถานะ "กำลังสร้างเว็บ..." แล้วรอสัก 1-3 นาที ระบบจะโชว์ลิงก์เว็บ + ชื่อผู้ใช้/รหัสผ่านแอดมินให้ทันทีในหน้าเดียวกัน — **ค่าใช้จ่าย Railway/usage ทั้งหมดตกอยู่ที่บัญชีลูกค้าเอง ไม่ใช่ของคุณ** token/URI ที่กรอกมาใช้แค่ตอนสร้างครั้งนั้น ไม่ถูกบันทึกเก็บไว้ในระบบเลย

ถ้าอยากให้คุณเป็นคนออกค่าใช้จ่ายแทนลูกค้า (เช่นรวมอยู่ในราคาขาย) ตั้ง `RAILWAY_API_TOKEN` ไว้เป็น fallback ได้เหมือนกัน — ใช้เมื่อลูกค้าไม่กรอก token/URI ของตัวเองมาเท่านั้น (ดูรายละเอียดใน `.env.example`)

**⚠️ ข้อควรระวัง:**
- Token ที่ลูกค้ากรอกมีสิทธิ์เต็มในบัญชี Railway ของเขา ระบบใช้แค่ครั้งเดียวตอนสร้างแล้วไม่เก็บไว้ — ควรบอกลูกค้าให้มั่นใจก่อนกรอก (token มาจากบัญชีของเขาเอง ไม่ใช่ของร้าน)
- ฟีเจอร์นี้เรียก Railway API จริง ควรทดสอบซื้อสัก 1 ครั้งด้วยตัวเองก่อนเปิดขายจริงกับลูกค้า เผื่อต้องปรับรายละเอียดตาม error ที่เจอ (ดู log การสร้างเว็บได้ในหน้าแสดงผลหลังซื้อ)
- ถ้าไม่ตั้ง `RAILWAY_TEMPLATE_REPO` ไว้ ช่อง "เปิดเว็บใหม่" จะไม่แสดง เหลือแค่ "ต่ออายุ" ตามปกติ ไม่กระทบการทำงานส่วนอื่น

## หมายเหตุสำหรับผู้พัฒนาต่อ

- Session อยู่ใน memory (`express-session` แบบ default store) — ถ้า scale เป็นหลาย instance ต้องเปลี่ยนไปใช้ session store แชร์กันได้ (เช่น connect-mongo)
- ยังไม่มี payment gateway จริง ปุ่ม "ชำระเงิน" เป็นการจำลองหักเงินจากกระเป๋าเงินในระบบเท่านั้น
- รูปภาพสินค้า/ตัวกรองทั้งหมดอ้างอิงเป็น URL ภายนอก (ไม่มีระบบอัปโหลดไฟล์)
- ทุกหน้าใช้ Tailwind ผ่าน CDN (`cdn.tailwindcss.com`) เพื่อความง่ายในการแก้ไข — ถ้าจะขึ้น production จริงจังควรเปลี่ยนไปใช้ Tailwind CLI/PostCSS build แทน
