# Security hardening — 2026-10-01

Scope: main storefront, all tenants served by this application, and the separate rent application. This is an application hardening review, not a guarantee against all compromise or an external penetration/load test.

The rent repository has its own security tests and this report is copied there. Its uploads allow raster formats; public upload URLs serve only logos/showcase images. Receipt routes require owner or admin access. Concurrent provider/admin approval credits once, and failed writes preserve balances. `npm test` passes there, including 25 EJS template checks.

## Verification limits and remaining work

- Four main UI/performance assertions remain failing: storefront owner-home script expectation, popup/performance expectation, old slipPath template assertion, and compact stylesheet smoke expectation. Baseline reproduction before security changes also fails these checks. Docker builds regenerate CSS bundles. The TrueMoney safety assertion was updated to the existing four-attempt default and passes. Security, storage rollback, order codec/revision and checkout checks pass. Do not describe the entire legacy suite as green.
- Mongo CAS tests use a mock collection; live application health verifies connectivity, not a real concurrent production-wallet test. Production balances/orders were not modified for testing.
- Rate limits are per process and reset on restart. They reduce application spam; volumetric DDoS requires upstream protection and origin restrictions. Legitimate traffic sharing an IP may hit a limit and should be monitored.
- Cloudflare is visible in public response headers, but dashboard login was not available during implementation. WAF rules, bot settings, TLS mode, DNS proxy coverage and origin bypass restrictions remain unverified until account access is available. Do not claim Cloudflare protection has been configured.
- VPS authentication/firewall, OS updates, database least-privilege credentials, offsite encrypted backups and a tested full restore remain unverified. Mongo is not published by the repository Compose configuration and the app proxy binds loopback, but deployed firewall state requires VPS access.
- Local `.bak` is one prior valid file, not a disaster-recovery backup. Rent JSON requires a single application instance; scaling it across processes requires a shared transactional database.
- CSP intentionally preserves existing inline/third-party scripts; it is not a nonce-based script policy. General stored-XSS coverage is limited to inspected boundaries. No claim of zero future bugs or leaks.
