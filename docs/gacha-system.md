# กล่องสุ่มเรท 1: สุ่มจริง รายรับเป้าหมายเฉลี่ย 97.50 บาทต่อชิ้น

ฟังก์ชันหลัก `src/services/gacha.js` · ทดสอบ `node scripts/test-gacha.js`

เชื่อมผ่าน `src/services/random-box.js` กับเส้นทางซื้อเดิมแล้ว ทั้งเว็บหลักและร้านเช่าใช้ logic เดียวกัน โดยข้อมูลและบัญชีสะสมแยกตามร้านและสินค้า การหักกระเป๋าเงิน ตัดสต็อก บันทึกคำสั่งซื้อ และบัญชีสะสมอยู่ใน transaction เดียวกัน พร้อมตรวจคำขอซ้ำ

## กติกาปัจจุบัน

- เรท 1 ราคาต่อครั้ง 1 บาท เปิดรวมได้ 1–500 ครั้งต่อคำสั่ง
- สุ่มจริงทุกครั้ง ไม่มีแผนล่วงหน้า ไม่มีเงื่อนไขว่าต้องได้เงิน 85–110 บาทก่อนจ่ายแต่ละชิ้น
- เมื่อสุ่มได้ชิ้นแรก มีโอกาส 40% ลุ้นชิ้นถัดไป ทำต่อได้สูงสุด 5 ชิ้นในการสุ่ม 1 บาทครั้งเดียว โดยจำกัดตามสต็อก
- ปรับโอกาสชิ้นแรกจากเงินที่เก็บรวมเทียบกับจำนวนชิ้นที่จ่ายแล้ว เพื่อให้รายรับต่อชิ้นเข้าใกล้ 97.50 บาทระยะยาว
- กันเกลือ **สะสมร่วมกันทั้งกล่อง**: เมื่อสุ่มกล่องนี้รวมครบ 110 บาทตั้งแต่รางวัลครั้งล่าสุด จะได้ขั้นต่ำ 1 ชิ้น ถ้าผลสุ่มครั้งนั้นยังเป็นศูนย์
- ใครสุ่มได้รางวัลจะรีเซ็ตตัวนับกันเกลือของกล่อง คนอื่นจึงไม่ได้มีสิทธิ์กันเกลือส่วนตัว การเปลี่ยนผู้เล่นไม่รีเซ็ตยอดสะสมของกล่อง
- ยอดน้อยตั้งแต่ 1 บาทมีลุ้นหลายชิ้น ยอด 50 บาทมีลุ้นหลายชิ้นจากศูนย์ได้จริง ยอดมากอาจได้มากหรือน้อยตามผลสุ่ม
- ถ้าของหมดระหว่างชุดเปิดจะหยุดหักเงินทันที

ราคา 97.50 บาทหมายถึง **เป้าหมายรายรับเฉลี่ยต่อชิ้น** ไม่ใช่มูลค่าประเมินของไอดี และไม่ใช่ยอดรับประกันทุกคลัง สต็อก 60 ชิ้นมีเป้าหมายประมาณ 5,850 บาท แต่ยอดจริงอาจมากหรือน้อยกว่านี้ กติกาใหม่ไม่ได้ล็อกรายรับต่อคลังไว้ที่ 5,100–6,600 บาท

## การปรับเปอร์เซ็นต์รวม

ใช้หน่วยสตางค์ ให้ L = เงินรวมที่เก็บ − จำนวนชิ้นที่จ่าย × 9,750

- L เป็นบวก: แจกน้อยกว่าเป้าหมาย จึงเพิ่มโอกาสออกรางวัล
- L เป็นลบ: แจกมากกว่าเป้าหมาย จึงลดโอกาสลง แต่ยังมีโอกาสสุ่มออกก่อน 110 บาทและยังมีลุ้นหลายชิ้น
- ตัวกันเกลือ 110 บาททำงานแม้ L เป็นลบ ไม่รอเก็บยอดชดเชยจนครบก่อนยอมจ่ายรางวัล

ค่าเริ่มต้นใช้ feedbackWindow = 50 และคำนวณทุกครั้งก่อนสุ่ม 1 บาท:

```text
U = clamp(5,000 + L + 100, 250, 487,500)
λ = U / 487,500
```

λ คือจำนวนชิ้นคาดหวังของผลสุ่มปกติในครั้งถัดไป **ยังไม่รวมรางวัลบังคับกันเกลือ** ฐานเท่ากับ `100 / 9,750` และค่า L เป็นตัวแก้เมื่อแจกเกินหรือแจกขาด เปอร์เซ็นต์ไม่ถูกยึดไว้ตลอดชุดเปิด แต่คำนวณใหม่หลังทุกครั้งที่เก็บเงินและจ่ายรางวัล

## รวมชิ้นโบนัสไว้ในสูตร

ให้ M เป็นจำนวนชิ้นสูงสุดที่ยังแจกได้ในหนึ่งครั้ง = min(5, สต็อกพร้อมแจก)

ถ้าชิ้นแรกออก จะลุ้นชิ้นถัดไปด้วยโอกาส c = 0.4 ทุกชิ้น โดยหยุดเมื่อไม่สำเร็จหรือครบ M ชิ้น

```text
E[จำนวนชิ้นเมื่อชิ้นแรกออก] = A = 1 + c + c² + ... + c^(M−1)
โอกาสชิ้นแรกออก = q = λ / A
```

กรณี M = 5 ได้ A = 1.6496 จึงรวมโอกาสโบนัสทุกชิ้นเข้าไปในการปรับโอกาสชิ้นแรกแล้ว ไม่ได้เพิ่มเปอร์เซ็นต์โบนัสนอกงบคำนวณ

เปอร์เซ็นต์รวมของจำนวนชิ้น:

```text
P(0) = 1 − q
P(k) = q × c^(k−1) × (1−c), เมื่อ 1 ≤ k < M
P(M) = q × c^(M−1)
```

ผลรวม P(0) ถึง P(M) = 1 และจำนวนชิ้นคาดหวังของผลสุ่มปกติ = q × A = λ

เมื่อกล่องสะสมไม่มีรางวัลครบ 110 บาท จะย้าย P(0) ไปเพิ่มให้ P(1) ทำให้ P(0) = 0 ส่วนโอกาสหลายชิ้นยังอยู่ รางวัลที่บังคับออกจะถูกนับในบัญชี L เพื่อให้รอบถัดไปปรับเปอร์เซ็นต์ชดเชยด้วย

โค้ดสุ่มด้วย `crypto.randomInt` โอกาสหลักใช้เศษส่วนจำนวนเต็มโดยตรง และโบนัสใช้ `randomInt(0, 5) < 2` จึงไม่ใช้ Math.random ใน production และไม่ปัดเปอร์เซ็นต์ก่อนเลือกผู้ชนะ

การรวมหลายกล่องเป็นหนึ่งคำสั่งเป็นการสุ่มจริงทีละ 1 บาทตามลำดับ พร้อมปรับบัญชีและตัวกันเกลือทุกครั้ง ไม่ใช่เพิ่มงบทีเดียวแล้วสุ่มด้วยเรทคงที่ ผลจึงสอดคล้องกันระหว่างกดครั้งละ 1/50/100/500 เมื่อใช้ RNG stream เดียวกัน

## สต็อกและ state

```js
const stock = [
  {
    stockId: 'account-001', // ไม่ซ้ำ หนึ่งรายการต่อหนึ่งไอดี
    rewardId: 'game-account',
    title: 'ไอดีเกม A',
    estimatedValueCents: 9500, // ข้อมูลประกอบ ไม่ควบคุมรายรับเป้าหมาย
    status: 'available',      // available / reserved / sold
    credentialsRef: 'vault/001',
  },
];

const state = {
  version: 4,
  poolId: 'shop-a:box-1',
  rate: 1,
  ticketPriceCents: 100,
  targetRevenuePerItemCents: 9750,
  totalCollectedCents: 0,
  totalPrizeItems: 0,
  drySpendCents: 0, // ยอดไม่ออกรางวัลของกล่องรวมทุกผู้เล่น
};
```

เลือก Stock ID จาก available แบบโอกาสเท่ากันโดยไม่ซ้ำ สินค้า sold/reserved ไม่ถูกเลือก ข้อมูลส่งมอบไม่อยู่ในรายการ rewards ที่ส่งกลับ

## เรียกใช้

```js
const { quote, draw } = require('./src/services/gacha');
const options = {
  stock,
  state: savedState, // null เฉพาะเมื่อกล่องนี้ยังไม่เคยมีบัญชีสะสม
  poolId: 'shop-a:box-1',
  rate: 1,
  ticketPriceCents: 100,
  ticketCount: 50,
};

const nextTicketOdds = quote(options);
// probabilityAnyDrop, probabilityMultiDrop และ dropCountProbabilities
// เป็นโอกาสของ 1 บาทครั้งถัดไป ไม่ใช่โอกาสทั้งคำสั่ง 50 บาท

const result = draw(options);
// หักเงินจริงตาม result.paymentCents
// เก็บ result.nextState และ result.nextStock พร้อมคำสั่งซื้อ

const publicResult = {
  ticketCount: result.ticketCount,
  paymentCents: result.paymentCents,
  prizeCount: result.prizeCount,
  rewards: result.rewards,
  drawResults: result.drawResults,
  stockExhausted: result.stockExhausted,
};
```

userId ไม่ใช้เป็นตัวแปรในสูตรสุ่มหรือตัวกันเกลือแล้ว การยืนยันผู้ซื้อ การหักกระเป๋าเงิน และการส่งมอบยังต้องทำใน route ที่เชื่อมจริงตามปกติ

## การบันทึก

ฟังก์ชันไม่แก้ input และไม่หักเงินจริง ผู้เรียกต้องตรวจ wallet และใช้ transaction/ล็อกบัญชีของร้านและกล่อง เพื่อ commit การหักเงิน สต็อก บัญชีสะสม คำสั่งซื้อ และ idempotency key พร้อมกัน ต้อง retry จาก state ล่าสุดเมื่อ concurrent writes ชนกัน

เก็บ state ต่อร้านและสินค้า ใช้ poolId จากข้อมูลฝั่งเซิร์ฟเวอร์ ไม่รับบัญชี เปอร์เซ็นต์ หรือตัวนับกันเกลือจากผู้เล่น ห้ามส่ง nextState/nextStock ทั้งก้อนให้ผู้เล่น เพราะเป็นข้อมูลบัญชีร้านและอาจมีข้อมูลส่งมอบ

เก็บ state ต่อเนื่องข้ามการเติมสต็อกและ restart รวมถึงหลังสต็อกหมด ห้ามรีเซ็ตบัญชีหลังรางวัลก้อนใหญ่ มิฉะนั้นการปรับโอกาสชดเชยจะหายไป

state ของโมดูลแยกเวอร์ชันเก่า 2/3 และ options แบบ RTP/dropSlots ถูกปฏิเสธก่อนสุ่ม ส่วนระบบกล่องสุ่มบนเว็บเดิมจะถูกย้ายผ่าน `randomBox.migrateData` ใน schema migration ของแต่ละร้านโดยอัตโนมัติ: ล็อกเรท/ราคาเป็น 1, เก็บยอดชำระและจำนวนรางวัลเดิม, คำนวณยอดไม่มีรางวัลจากลำดับคำสั่งซื้อ, คืนสต็อกที่ระบบสุ่มเดิมจองไว้ และสำรองรอบเดิมใน `randomBoxMigrationBackup` ประวัติคำสั่งซื้อ กระเป๋าเงิน และไอดีที่จ่ายแล้วไม่ถูกลบ การย้ายซ้ำไม่รีเซ็ตบัญชี

ทดสอบเส้นทางเว็บหลักด้วย `SMOKE_RANDOM_BOX_ONLY=1 node scripts/smoke-server.js` และร้านเช่าด้วย `node scripts/test-random-box-tenant.js` (PowerShell ใช้ `$env:SMOKE_RANDOM_BOX_ONLY='1'` ก่อนรัน)

## ทดสอบและ simulation

รัน `node scripts/test-gacha.js` ตรวจสุ่มจริงยอดใหม่ 1/50/100 บาทได้สองชิ้น, โอกาสรวมทุกจำนวนชิ้นบวกกันเป็น 100%, บัญชีปรับโอกาสหลังแจกมาก/น้อย, กล่องสะสมครบ 110 บาทต้องออกแม้เปลี่ยนคนเล่น, รีเซ็ตเมื่อใครก็ได้ชนะ, ไม่จ่ายไอดีซ้ำ, input ไม่ถูกแก้ และหยุดหักเงินหลังสต็อกหมด

ทดสอบกดชุดต่างขนาดให้ผลเหมือนกันตาม RNG seed และทดสอบเปลี่ยนจำนวนผู้เล่นแล้วบัญชี/ตัวกันเกลือยังให้ผลเหมือนเดิมเมื่อ seed เดียวกัน

จำลอง 200,000 ครั้งต่อเงื่อนไข โดยเติมสต็อกต่อเนื่องและเก็บ state เดิม:

| จำนวนผู้เล่น | ยอดต่อคำสั่ง | รายรับเฉลี่ยต่อชิ้น | คำสั่งได้ ≥2 ชิ้น | คำสั่งไม่มีรางวัล |
|---:|---:|---:|---:|---:|
| 1 | 100 บาท | 97.4659 บาท | 6.70% | 8.65% |
| 10 | 100 บาท | 97.4184 บาท | 6.80% | 8.30% |
| 100 | 100 บาท | 97.4659 บาท | 7.30% | 8.90% |
| 10 | 50 บาท | 97.4184 บาท | 2.55% | 53.25% |
| 10 | 200 บาท | 97.4659 บาท | 84.70% | 0.00% |

ตัวเลขนี้เป็นผลจาก seed และลำดับคำสั่งที่ใช้ทดสอบ ไม่ใช่เปอร์เซ็นต์คงที่ที่แสดงให้ผู้เล่นทุกคนได้ โอกาสจริงต้องคำนวณจากบัญชีและตัวนับกล่องล่าสุด

97.50 บาทเป็นเป้าหมายที่ feedback ควบคุมระยะยาว ไม่ใช่การรับประกันรายรับของทุกสต็อกหรือทุกช่วงเวลา ถ้ารางวัลประเมินมูลค่าเฉลี่ย 97.50 บาท การรักษารายรับเฉลี่ยระดับเดียวกันจะให้ RTP ตามมูลค่าประเมินใกล้ 100% ส่วนกำไรต้องคิดจากต้นทุนจริงของร้าน
